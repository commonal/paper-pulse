# 研脉 · PaperPulse

以论文为核心的研究热点追踪与 AI 解读应用，把论文原文、解析证据和代码资源关联在一个页面中。首轮采用单人本地工作空间，先验证“导入论文 → 解析正文 → 生成可回跳解读”的闭环。

## 已实现的第一条流程

粘贴 arXiv 链接后自动预览标题、作者、日期、摘要和版本，确认后选择仅保存到我的论文，或保存并将正文解析任务交给持久化 worker 队列；也可直接导入本地 PDF，再补充版本和代码链接 → 论文热点首页浏览/搜索 → 论文详情的 AI 解读、原文和代码资源 → 点击证据块回到原文页。正文材料通过 MinerU API 的“上传 → 轮询 → 下载 ZIP → 归一化证据块”链路生成，保留 Markdown、页码、标题层级、公式、表格、图注和 `content_list.json` 定位；未配置 `MINERU_API_TOKEN` 时，arXiv 仅使用明确标注的 HTML 轻量回退，不冒充 MinerU 结果。AI 解读要求每个可验证主张绑定真实证据块，并单独覆盖实验设置与结果。解析和解读只由 worker 执行，页面操作只负责入队并读取任务状态。

论文、正文材料和 AI 解读持久化到 PostgreSQL；解读保存模型、提示版本、状态和证据块 ID。同篇论文可保存多份原文，每份独立保留 PDF、正文材料、双语简介、解读、图表和任务记录；切换不会删除旧版本。arXiv 自动发现以规范化 ID 合并论文记录，发现新修订时仅新增可选版本，不覆盖当前文章或自动购买新精读。原文由 PDF.js 上下连续滚动阅读，页码跟随视野，也可输入页码跳转；解读引用按可靠解析坐标定位对应证据段落，用原生文字几何位置逐行黄色高亮。无可靠段落定位时明确提示，当前不是独立单句引用或个人划线。历史原文与高亮独立，附近页面按需渲染。参考research-pulse工作台并已在BERT真实验证，见[连续阅读与高亮](../evidence/2026-10-10-pdf-scroll-highlight.md)。目前没有PDF文字选择或持久区域批注。AI解读侧可记录整篇笔记、段落与图表批注，研究聊天暂不展开。

### AI解读侧阅读笔记

BERT图表流程曾因完整回答包含8条观察、旧排版限制最多6条而停止。后续三篇真实评测又发现Dropout表格需要14条短观察：现条数只作为写作建议，不因观察数量拒绝完整回答；每条长度、真实引用、最多六张图和独立原图核查继续检查。只对完整且输入完全相同的已保存失败回答恢复，新失败说明具体字段。此前恢复记录见[图表结构失败修复](../evidence/2026-10-09-bert-visual-recovery.md)。

在解读顶部打开“我的笔记”，或点击段落、图表旁低调的“记一笔”。桌面为可收起右侧栏，窄屏为底部抽屉；历史解读也能记笔记。笔记独立于生成文章，绑定原文版本、创建时解读签名/回执、段落原句或图下解释、原文证据及图像SHA。重新精读不覆盖个人文字；关联内容改变时保留旧原句并提示核对，不将原批注跳到另一段。可按已有笔记切换整篇及批注，回跳解读或对应原文。

停止输入约900ms或离开编辑框自动保存，页面显示待保存/保存中/已保存/失败/冲突。每条笔记串行保存，保存期间继续输入不会被旧回答覆盖；新笔记稳定UUID防止响应未知后重复创建。草稿存于当前标签页sessionStorage，刷新及站内返回可恢复，关闭标签页前须确认已保存。失败保留草稿并显式重试；另页更新触发修订号冲突，可查看服务器文字、采用服务器版本或明确保留自己的草稿保存。解读变化而尚未落库的批注，可保留原关联文字另存整篇笔记。Markdown预览展示服务器已保存并消毒的内容。笔记全部走管理员HTTP接口，不调用模型、不进入阅读队列。原有私有notes.md接口保留；本次未接导出界面、PDF划线、批量操作或笔记删除。验收见[解读侧笔记记录](../evidence/2026-10-09-reading-notes.md)。

关注与检索设置提供八个预设方向：RAG 与信息检索、多模态大模型、大模型推荐、Agent 与工具使用、训练与对齐、推理与评测、高效训练与推理、代码与软件工程；AI 热点发现单独控制。每个方向可选细分主题、重点关注、标题精确匹配或标题/摘要广泛匹配，以及补充词和排除词。保存前可用当前表单预览本地已收录候选及命中理由，不访问外部信源或触发付费请求。旧自定义分类与关键词保留，点击“使用推荐规则”才切换到预设。

候选论文页按这八个方向及“其他方向”提供分类数量和快速筛选，可组合关键词、待精读/已有解读状态，每页24篇。分类根据标题与摘要匹配，一篇可属于多个方向，跨检索来源合并成一张卡片并保留全部命中理由；分类不自动开启关注方向或购买解读。打开论文后返回会保留筛选和页码。验证见 [候选分类筛选记录](../evidence/2026-10-08-candidate-direction-filters.md)。

最近 7 天候选、每日最多 3 篇（热点最多 1 篇）和 7 天/前 7 天 arXiv 数量对比继续保留。个人方向按近七天主推荐次数轮换，次数相同先选重点关注，再选较久未推荐的方向；跨方向同篇去重，开启更多方向不会增加每日配额。自动发现默认关闭；部署端设置 `PAPER_DISCOVERY_ENABLED=true` 后，worker 每天 06:00（Asia/Shanghai）运行。今日阅读页显示最近检索成功、下次计划及入选/可读/完整完成/处理中/等待/未完成计数，区分尚未到时间、今日未更新、检索失败、成功但没有入选和预算等待。06:00 是检索开始时间，解读随后完成；状态来自已保存的计划、运行和阅读任务，不代表后台在线心跳，打开页面或刷新状态只读数据。MinerU 外部调用也默认关闭；只有设置 `MINERU_CALLS_ENABLED=true` 且在后台为 `mineru` 配置非零预算后才会调用。默认回退使用 arXiv HTML 轻量解析。方向规则及真实验证见 [关注与检索设置验证](../evidence/2026-10-08-direction-preferences.md)。

每日发现按方向保存最近窗口和趋势窗口的进度；一个方向或趋势统计失败不会丢弃其他候选。自动检索与手动 arXiv 元数据预览共用串行请求和至少3.1秒间隔，429冷却时间落库，重启不清空。429、5xx和连接超时按15/30/60/120分钟延迟恢复，并尊重更晚的Retry-After；每个方向的每个窗口最多五次尝试，永久错误停止并保留原因。后台每五分钟检查当天漏跑和到期等待，06:00前不补跑，不重复检索已完成窗口或回补历史日期；已有时效内候选仍按当前关注规则、每日配额和近期去重进入精读。页面展示检索等待、各方向完成情况和最早重试时间；部分检索成功不冒充全量成功。见[日更检索恢复记录](../evidence/2026-10-10-discovery-recovery.md)。

CCF A 高引与经典论文由 OpenAlex 每周检索一次，也可显式点击“更新高引论文”交给 worker 更新；检索从1900年起，不再限制近十年。首期白名单聚焦人工智能、数据库/内容检索、图形学与多媒体、交叉/综合方向的 CCF A venue；按 OpenAlex 正引用计数排序，支持关注方向、关键词、年份、会议/期刊及精读状态组合筛选，每页24篇。点击“开始精读”后才建立站内论文和阅读任务，worker 获取开放 PDF，或读取上传的原文，再执行现有完整 Skill 流程。已完成论文可从高引页和已精读库打开；重复选择复用论文和正在处理的任务，不批量购买候选解读。

外部检索默认关闭，设置 `PAPER_OPENALEX_ENABLED=true` 后启用；`OPENALEX_API_KEY` 可选，只能配置在服务端。配置密钥的检索经过 `openalex` 回执与请求预算，默认预算为零，需显式设置后使用；同一输入可复用结果。本机匿名查询已真实验证，不配置密钥或增加已有模型/MinerU预算。首期白名单不是完整 CCF A 目录，venue 命中也不能证明单篇论文属于 Full/Regular paper；引用高不直接等于经典。真实 Dropout 精读与限制见 [高引经典阅读验证](../evidence/2026-10-08-classic-paper-reading.md)。

论文解读必须给模型明确的 JSON 结构和五个章节，生成后校验证据 ID；只有内容与回执同时保存成功才显示完成。当前 DeepSeek Flash 部署使用 `LLM_EXTRA_JSON={"thinking":{"type":"disabled"}}`、`LLM_REASONING_TOKENS=0`，让结构化解读直接输出正文；论文解读的输出上限为 6,000 token、等待时间为 120 秒。其他供应商按自己的参数配置，不依据模型名字猜测推理开关。预算耗尽或请求结果未知时任务保留为等待状态，每五分钟检查额度与回执后恢复；无效模型输出会保留失败回执，等待检查配置后手动重试。候选库不自动解析，只有每日选中的最多三篇或显式选择精读的手动论文进入处理队列。预算按滚动 24 小时计数，配置时要覆盖相邻两个自然日的任务与有限重试；预算是请求次数熔断，不是金额或输出 token 上限。

默认精读先检查正文覆盖，再生成初稿并独立逐条核查；实验节分别说明数据集、基线、指标、结果和限制。重试前重新校验完整的已保存回答；仅在论文、提示词版本、正文版本和证据引用全部匹配时复用。截断、未知结果和材料已更新的回答不能直接恢复。

原文核查失败后，详情页显示问题主张、待修订文字、证据类型、核查判断及对应原文页，可展开原句和回跳PDF。可填写修订建议或留空按原文自动修订；worker只修订失败项，再独立检查文字准确性与证据边界，所有主张仍通过原文ID及摘录校验后才发布，并继续图表流程。其他已核查段落及原有文章保持；预算等待保留输入，完整且精确匹配的修订稿可复用。正文或版本改变时拒绝旧修订，可明确重新精读。图表核查也选择原文片段编号，由宿主取回原句，避免模型改写LaTeX或表格摘录。真实恢复与费用记录见[核查失败修订验证](../evidence/2026-10-09-review-repair.md)。

请求预算作为异常熔断配置。本机目前为4次/分钟、24次/小时、66次/滚动24小时（日上限在核查器校准时由60小幅增加），每日选入仍最多三篇；通用设置命令 `node --env-file=.env scripts/configure-paper-budgets.ts --apply` 的默认日上限仍60，不在迁移或浏览页面时执行。页面分别显示额度等待、模型未开启、回执未知和已有请求，额度等待附实际使用量及预计检查时间。正常停止且正文内容完整的回答，仅允许修正末尾 JSON 容器括号，仍需通过结构、真实证据与独立原文核查；供应商原回答保留，修复信息附在回执审计中。输出长度截断、字符串截断和内部 JSON 错误继续拒绝。

今日阅读、论文搜索和详情展示中文标题、英文原题及简短中文简介。新论文通过精读初稿和独立核查生成双语展示与五节解读，并原子保存；已有完整展示继续保留，显式重新精读时才更新。中文标题与简介可检索，原始标题与摘要保持不变。展示内容绑定标题、摘要及版本，元数据更新后旧译文不再展示。候选库不批量付费翻译，入选或手动处理后才生成；尚未生成时保留原始摘要。所有生成仍由 worker 执行，页面只读取已保存结果。

解读详情按文章段落排版，出处改为可点击的小序号，同一证据块复用编号，完整引用列表默认折叠。解读完成后，worker 自动从具有可靠定位的原文图表目录中选择最多六张，不设硬性最少数量，在研究问题、方法、实验或局限段落中插入，并生成“怎么看、说明什么、需要注意”三段中文解释及选图理由；另一轮模型回读图注、表格文本和正文核查，只有真实引用和连续摘录均通过才保存。图表从本地 PDF 裁剪显示，点击返回原页；图像边框附近的 PDF 原生文字与图像对象会补齐，避免标签被解析框切掉。访问页面不调用模型或 MinerU，未知定位或版本变化时不猜测插图位置。旧文章可在文末选择“优化图表解读”，失败可显式重试，预算不足时自动等待恢复。文本模式下，每篇新图表解读正常增加两次模型请求，候选库不批量处理。实测见 [自动图表解读记录](../evidence/2026-10-07-auto-illustrations.md) 和 [另外两篇论文验证](../evidence/2026-10-07-two-paper-illustration-validation.md)。

### 精读执行与质量评测

“精读评测”页独立记录每次完整流程及状态变化，分别统计首次无中断完成、恢复后完成、等待和失败；展开可查看阶段、原错误、回执和恢复过程。旧任务没有起始历史时另列，不猜测成功率。管理员可显式对已发布解读评分：冻结原文版本、文章和图表，worker逐条核查主张，给出六维评分、问题及遗漏，并回跳对应版本原文；评分不覆盖文章或个人笔记。浏览、刷新和下载报告不调用模型。当前评分与生成使用同一模型，量表未人工校准，属于审查意见。设计与真实三篇结果见[精读评测](../paperpulse/reading-evaluation.md)及[验收记录](../evidence/2026-10-10-reading-evaluation.md)。

核查器已针对BERT误拒绝与Dropout正文/表格数值冲突进行受控校准。修订审查只检查当前文字，并将未报告事项的查阅范围与直接证据分开；质量报告可展开逐项原文数字读取、原文自身冲突及正确/故意错误样本的判断结果。表格保留真实行列，伪数字继续拒绝。样本标签由Agent对照原文建立、尚待人工复核，不视为总体准确率或自动发布门槛；旧失败与旧量表报告保留。见[核查器校准记录](../evidence/2026-10-10-reviewer-calibration.md)。

## 技术结构

自动选图现最多六张，不设硬性最少数量，优先覆盖方法、主结果及关键消融。已完成三张策略的文章继续保留，显式优化时按六张策略重新选取；无需重跑正文或解析。BERT已真实完成六张原图解读与独立核查，见[六张图表验收](../evidence/2026-10-09-six-figures.md)。

### 默认 Skill 阅读流程

自动日更、手动导入和重新精读统一执行“正文解析 → 覆盖检查 → Skill 精读 → 逐条原文核查 → 自动选图和解释”。精读采用固定版本的开源 `techdou/paper-reading` 核心文件，保留许可证与来源；由现有 worker、模型回执和预算控制执行。未启用视觉时，普通有图表的新论文正常需要四次模型请求；无可靠图表时只需精读和核查两次。MinerU 请求另计。

`paper_reading_tasks` 单独保存阶段、任务编号、选项、覆盖报告和回执；页面显示进度，旧文章在更新失败时仍可阅读。预算不足、服务开关关闭或结果未知时等待恢复；内容校验失败需显式重试。每五分钟的恢复调度只恢复真实待办，不处理未入选候选。新任务替代旧任务后，旧任务无法发布。正文及图表核查选择原文片段编号，系统取回原句并补齐对应引用，避免模型重写 LaTeX 或漏写重复的引用字段；原始回答和引用修复记录保留。该检查证明出处位置，语义和实验结论仍需要抽查。

先重启 worker 加载代码，再入队：

```powershell
node --env-file=.env scripts/eval-paper-reading.ts --paper <论文UUID>
```

可用 `--visual-notes <JSON路径>` 传入已核对 PDF 哈希、证据块及页码的先行图像检查记录。正文精读阶段仍接收文本，不把人工检查记录等同于模型看图；图表阶段现可直接接收PDF原图，见下方视觉流程。超过 180,000 字符的非参考文献材料会暂停并要求制定分段范围，不静默删减。初稿及审校正常各需一次模型请求，原文摘录、引用和所有主张都通过检查后才原子更新原有解读与双语展示；失败时保留旧页面。

人工校订用 `--review-corrections <JSON路径>` 显式绑定同一输入的已保存审校回执，可恢复原文摘录或补齐主张条件；修改后的内容仍需通过结构、引用与逐字出处检查。原始模型回答保留，校订原因、图像记录、核查结果存入回执，精确输入重放复用已接受校订。运行材料按任务保存在 `.data/eval/paper-reading/<UUID>/<run_id>/`，不提交 Git。首篇 AffordCraft 的结果与验证边界见 [精读试验记录](../evidence/2026-10-07-paper-skill-pilot.md)。

### 视觉图表解读

模型实际支持图片且声明`LLM_VISION=true`时，图表worker从当前PDF裁切最多六张已选图表，绑定PDF哈希、页码、定位与图片SHA。先只依据原图和图注生成图像观察，不给旧解读或正文；再将相同原图、图注与正文交给独立核查，区分可见内容、文字补充和无法确认的信息。核查引用继续使用原文片段编号，只有图文判断和出处均通过才发布。原图渲染在限时worker线程内执行，不由读者页面触发。

已有文本解读继续可读，可显式“结合原图重新解读”；页面逐图标明“已结合原图独立核查”或“依据图注、表格文本和正文解读”，并可展开观察、正文补充及不确定内容。未启用或模型未声明视觉时沿用明确标记的文本图表流程。渲染失败、额度等待或核查失败保留旧解释，不冒充视觉完成。

复用已有选图的视觉升级正常需两次模型请求，新论文先选图再视觉生成/核查需三次图表请求；正文精读与核查另计两次。有可靠图表的新论文完整流程通常共五次模型请求，候选库不批量购买、旧图表也不自动升级。默认不启用视觉，本机已核对DeepSeek官方能力并显式启用。实际三图验证及限制见[视觉图表验收](../evidence/2026-10-09-visual-illustrations.md)。

视觉核查同时逐条对照正文主张（含一句话结论），区分明确一致、明确矛盾和无法由选中原图判断；看不清不当作矛盾。视觉流程v3发现有原图定位的正文矛盾后，只修订对应主张和必要的中文简介，再用同一组原图与原文独立复核正文、证据边界及图下解释。正文修订和图表在同一事务内保存，保留其他段落、主张ID和中文标题；失败保留旧文章并显示问题段落、原图页码及待核查修订，原有“继续处理”入口可恢复。预算等待复用完整回答，不重做解析或整篇精读。没有矛盾不增加模型请求，有矛盾通常增加两次请求，不无限自动重写。旧视觉v2可显式升级；没有批量重买或数据迁移。仅核查已选的最多六张图，不等于全文视觉验证。验证见[图文闭环记录](../evidence/2026-10-09-visual-body-closure.md)。

复用 AIHOT 的 TypeScript / React Router SSR / Fastify / PostgreSQL，以及站点壳层、热点导航和模型调用接口。新增业务集中在 `modules/papers/`，前端只经 HTTP 访问 API；论文、材料和解读接口使用管理员身份和 CSRF 校验，并禁止共享缓存。底座的新闻功能仍保留在上游代码中，论文页面以论文热点和证据型解读为主。

## 网站入口

网站入口统一为桌面侧栏的四组：阅读（今日阅读、我的论文、已精读论文、阅读记录）、发现（候选论文、CCF A 高引、方向趋势）、AI 资讯（新闻精选、全部动态、热点榜、日报/周报、主题）、个人与设置（关注与检索设置、新闻收藏、外观与设置）。窄屏底栏对应阅读、发现、资讯、我的，各栏目顶部提供二级入口。“已精读论文”只展示已有可阅读 AI 解读的论文，按解读更新时间排序，不依赖个人是否标记已读；候选、处理中和失败且没有可阅读解读的论文不进入该列表。阅读记录按手动状态筛选；停留超过 30 秒仅计入本地阅读停留统计。论文详情返回来源列表时保留关键词和筛选。原有新闻 URL 与功能继续保留。

我的论文管理主动保存和手动导入的论文，支持个人阅读状态、已精读、方向、标签和搜索，置顶优先、按加入时间排序。导入默认仅保存；候选和高引论文也可以加入并精读。重复链接、稳定 arXiv ID、规范化 DOI 和相同 PDF 复用已有论文及解读，不覆盖已有不同版本的原文。移除收录保留论文、PDF、笔记和解读。未知元信息保留待补全；PDF 上传后自动提取首页线索并对照标题与作者；DOI 与 arXiv 支持查询预览。扫描版由 worker 执行 MinerU OCR，经过已有预算与回执，正文结果可复用于精读。未知与模糊匹配由用户核对，身份一致不代表版本或全文完整已核验。验证见 [我的论文与元信息](../evidence/2026-10-08-personal-paper-collection.md)。

PDF/DOI 自动身份流程及实际BERT、Dropout、扫描样本的核验见 [身份识别验证](../evidence/2026-10-09-pdf-doi-identity.md)。

详情的“原文与解读版本”可添加同篇另一份 PDF、查看历史文章、仅设为当前或显式切换并精读。相同 PDF 不重复存储；正在处理或结果未知的请求完成前禁止切换。历史页的引用、图表和 PDF 对应所选版本，精读须先切为当前；已精读库仍能找到旧版文章。个人收录和阅读状态属于整篇论文，笔记按原文件定位。新增归属由使用者确认，外部身份对照只作为核验线索，不能证明两份正文等价。版本验证见 [原文版本管理](../evidence/2026-10-09-paper-original-versions.md)。

## Windows 本地运行

需要 Node.js 24.11+、npm 和 Docker Desktop（PostgreSQL）。

```powershell
npm ci
npm run local:setup
npm run typecheck
npm run build -w @aihot/web
npm run local:start
```

访问 http://127.0.0.1:5320 。本地启动会同时运行 API（4321）、worker 和 Web；worker 负责消费论文解析与解读队列。独立数据库容器 `paper-pulse-db` 使用端口 5545 和卷 `paper-pulse-pgdata`。停止服务：`npm run local:stop`，不会删除数据库。重启：`powershell -ExecutionPolicy Bypass -File scripts/local.ps1 restart`。

此工作目录已经生成忽略 Git 的 `.env` / `.env.test` / `.local/db.env`，凭据不写入文档。其他机器运行 `npm run local:setup` 会自动生成独立开发配置。手动部署时参考 `.env.example`，配置自己的数据库和密钥。本地使用上游的 `DEV_AUTH_ROLE=admin` 模式，仅监听 127.0.0.1；上线前必须关闭开发身份，配置真实管理员密码/会话密钥并设 NODE_ENV=production，重新验证私有笔记访问。
