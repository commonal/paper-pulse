# 论文质量与证据检查清单

## 1. 主张—证据对应

为每个主要主张寻找对应证据：

| 主张类型 | 最低证据要求 |
|---|---|
| 性能更好 | 同数据划分、同指标、强基线、明确提升幅度 |
| 更鲁棒 | 多种扰动、缺失模态、噪声或域偏移测试 |
| 更高效 | 参数量、FLOPs、吞吐、延迟或训练成本 |
| 泛化更强 | 跨数据集、跨区域、跨传感器或跨时间测试 |
| 模块有效 | 单模块消融、替代设计和组合实验 |
| 不确定性可靠 | 校准指标、风险覆盖、OOD 或拒识实验 |

没有相应证据时，只能写“作者声称”，不能写成已被证明的事实。

## 2. 实验公平性

- 训练/测试划分是否一致；
- 输入数据和模态是否一致；
- backbone 和预训练是否一致；
- 数据增强和训练预算是否相近；
- 是否引用旧论文数字而没有重新训练；
- 是否对所有方法使用相同指标实现；
- 是否存在额外数据、人工规则或后处理。

## 3. 领域专项检查

通用检查无法覆盖所有领域的数据泄漏与评测惯例。遥感论文应额外读取 [remote-sensing.md](remote-sensing.md)。其他领域只在用户任务确有需要时增加相应专项检查，不要把单一领域规则硬套到所有论文。

## 4. 消融质量

高质量消融应回答：

1. 新模块本身是否有效；
2. 当前设计是否优于可替代设计；
3. 多模块是否互补；
4. 关键参数是否稳定；
5. 提升是否来自更强训练技巧；
6. 额外成本是否值得。

## 5. 数字解释

每个关键数字至少附带：

```text
数据集 + 指标 + 对比方法 + 绝对提升 + 实验条件
```

避免只写“提高 2%”。需要确认是 2 个百分点还是相对提升 2%。

## 6. 复现风险

- 数据和标签是否公开；
- 划分文件是否公开；
- 预处理是否完整；
- 模型配置是否完整；
- 随机种子和重复次数是否给出；
- 预训练权重和依赖版本是否可用；
- 硬件预算是否现实；
- repo 与论文是否一致；
- 是否有未公开模块或数据。

## 7. 可信度表达

推荐使用：

```text
证据充分：多数据集、强基线、公平设置、完整消融和稳定性分析
证据中等：主要结果可信，但泛化、效率或统计稳定性不足
证据有限：实验规模小、比较不完整或关键设置不透明
无法判断：缺少正文、表格、附录或代码，当前材料不足
```

## 8. 交付前检查

- 是否明确了论文事实与解释性推断；
- 是否核对了关键数字而非只复述摘要；
- 是否说明比较公平性；
- 是否说明证据边界；
- 是否指出至少一个限制或未验证主张；
- 是否给出继续精读、选择性阅读或停止投入的判断；
- 是否避免把 Related Work 直接判定为不重要；
- 是否避免因为 venue 或作者名气直接替代内容判断。
